## Usage

<p>
  DatePicker supports three selection modes: `single`, `multiple`, and `range`.
</p>

```tsx
import { createSignal } from "solid-js";
import { DatePicker } from "@photon-ai/kumo-solid";

export default function Example() {
  const [date, setDate] = createSignal<Date>();

  return <DatePicker mode="single" selected={date()} onChange={setDate} />;
}
```

## Full Popover Example

<p>Here's a complete example showing how to compose DatePicker with Popover:</p>

```tsx
import { createSignal } from "solid-js";
import { DatePicker, Popover, Button } from "@photon-ai/kumo-solid";
import { CalendarDotsIcon } from "~/components/icons";

export function DatePickerDropdown() {
  const [date, setDate] = createSignal<Date>();

  return (
    <Popover>
      <Popover.Trigger
        render={(triggerProps) => (
          <Button {...triggerProps} variant="outline" icon={CalendarDotsIcon} />
        )}
      >
        {date()?.toLocaleDateString() ?? "Pick a date"}
      </Popover.Trigger>
      <Popover.Content class="p-3">
        <DatePicker
          mode="single"
          selected={date()}
          onChange={setDate}
        />
      </Popover.Content>
    </Popover>
  );
}
```

## API Reference

<p>
  DatePicker provides a Solid-native, type-safe API inspired by
  <a
    href="https://daypicker.dev/api/interfaces/PropsBase"
    target="_blank"
    rel="noopener noreferrer"
  >
    DayPicker
  </a>
  . It is implemented natively for Solid and does not ship `react-day-picker`.
  Key props include:
</p>
<ul class="mt-4 list-disc list-inside space-y-2">
  <li>
    `mode` — `"single" | "multiple" | "range"` — Selection mode (required)
  </li>
  <li>`selected` — Currently selected date(s)</li>
  <li>`onChange` — Callback when selection changes</li>
  <li>`numberOfMonths` — Number of months to display</li>
  <li>`disabled` — Dates that cannot be selected</li>
  <li>`min` / `max` — Min/max selection constraints</li>
  <li>`footer` — Content rendered below the calendar</li>
  <li>`locale` — Intl locale or Kumo locale settings</li>
  <li>`className` — Additional CSS classes</li>
</ul>
<p class="mt-4 text-kumo-subtle text-sm">
  The
  <a
    href="https://daypicker.dev/docs"
    target="_blank"
    rel="noopener noreferrer"
  >
    DayPicker documentation
  </a>
  is useful background for the familiar concepts, while the Kumo prop types
  remain the source of truth.
</p>

### Differences from DayPicker

  <p>
    For consistency with other Kumo form components, DatePicker uses `onChange` instead of DayPicker's `onSelect`.
    Full type inference is preserved — TypeScript will correctly narrow the callback signature based on the `mode` prop.
  </p>
</ComponentSection>
